# ドメインの同値関係を型自身が定義する

移植元: [amadeus-ngの同名規則](https://github.com/amadeus-dlc/amadeus-ng/blob/537c4e56a838a4cb28f6564d4c0add1d4adfe915/aidlc/spaces/default/knowledge/aidlc-shared/coding-rules/domain-equality.md)。2026-09-05にTypeScriptと当該の裁定へ適用し直した版。

## 規則

- 値オブジェクトの同値関係は`equals(other)`で表す。TypeScriptの`===`はオブジェクトの参照同一性であり、値の同値関係の代用にしない。
- 何を同値とするかはドメインの意味で決める。ポリシーやキャッシュなど、同一性に無関係なフィールドを機械的に含めない。
- エンティティの同一性は識別子で判断する。状態の全フィールド比較と混同しない。
- ハッシュを同値判定に利用するなら、同値な値が同じハッシュになるようにする。
- 同値関係には反射性・対称性・推移性が必要。仕様上重要な境界値も確認する。

## 順序との区別

`compareTo`などの順序関係は、必ずしも同値関係ではない。例えば先行ゼロを含むIDの並びと、原文を保持する値の等価性は別の契約になり得る。並べ替えのために等価性の意味を変更しない。

移植元の`Eq`／`PartialEq`の採用方針は、演算子をオーバーロードできないTypeScriptでは`equals`へ対応づける。
適用範囲と優先関係は[共有規則の入口](README.md)を参照。
