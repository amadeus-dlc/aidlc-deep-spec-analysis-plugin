# 抽象データ型 — 表現ではなく操作と契約で定義する

移植元: [amadeus-ngの同名規則](https://github.com/amadeus-dlc/amadeus-ng/blob/537c4e56a838a4cb28f6564d4c0add1d4adfe915/aidlc/spaces/default/knowledge/aidlc-shared/coding-rules/abstract-data-type.md)。2026-09-05にTypeScriptと当該の裁定へ適用し直した版。

## 原則

ドメインプリミティブ（DP）・値オブジェクト・エンティティは、利用者が内部表現を知らずに使える抽象データ型として設計する。フィールドをクラスで包むだけでは十分ではない。型自身が操作と不変条件を所有し、呼び出し側は公開した契約に依存する。

- カプセル化の単位はクラスである。同じパッケージにあることを理由に内部状態を公開しない。
- 不変条件は構築時に成立させ、その後の操作でも維持する。詳しくは[生成規則](factory-naming.md)。
- 判断は値を持つ型へ置く。呼び出し側がフィールドを取り出して同じ判断を繰り返さない。
- 配列やMapの操作と不変条件は[ファーストクラスコレクション](domain-object-kinds.md)へまとめる。
- 1ファイル1公開型とし、公開面はファサードで明示する。

## 暴露と境界変換

`asString`・`toDocument`という名前を付ければ内部表現を公開してよいわけではない。先に、型の判断として答えられないかを検討する。外部契約への変換が必要なら、その必要性と所有権を明記する。返した配列やオブジェクトを通じて内部状態が変わらないようにする。

外部形式のDTO、公開する式の構造、汎用のResultなどはドメインの抽象データ型とは役割が異なる。適用範囲は既存のPublished Language・層規則に従う。
適用範囲と優先関係は[共有規則の入口](README.md)を参照。
