# 取得失敗の握りつぶしを防ぐリンターと横展開修正

## 対象と境界

基準コミットは `b03eaab5f8e1a23ebab30f7d465c39612dbe4102`。`src/*/adapter`、`src/*/usecase`、`src/entries` を TypeScript AST と型情報で検査する。依存パッケージ、ドメイン層、生成済みバンドル、テストの fixture は検査対象外。生成バンドルは `build-tools.ts --check` でソースとの一致を別途確認する。

`bun run check` と `bun run lint` に組み込んだ。違反は終了コード 1、プロジェクト読込・構文・型エラーや対象ファイルなしは終了コード 2。`--project` と `--json` で別コミットの実測を再現できる。

## 検査する契約

| ルール | 禁止する挙動 |
| --- | --- |
| process-output-classification | 子プロセスの出力に含まれる一般語から失敗・deadlockを断定する |
| filesystem-error-collapse | 読取例外を、不在の確認なしに空集合・null・false等へ変換する |
| filesystem-existence-gate | existsSyncで取得対象を除外し、取得障害を不在・成功へ変換する |
| repository-error-collapse | RepositoryErrorを不在確認なしに正常・対象外へ変換する |

例外を捕捉する範囲は I/O や JSON 解析などの境界処理に限り、ドメインの `of` が投げる契約違反を握りつぶさない。任意入力の不在は ENOENT に限る。ENOTDIR、EISDIR、EACCES 等は原因付きの取得失敗として伝える。

## 修正した取得経路

共通のファイル・ディレクトリ読取 API を Result 化し、要件、設計、参照検査、検証結果の保存・再読込、ロック所有者情報、doctor、Quint の実行環境検出へ適用した。インストール判定も通常ファイルの実在を確認し、読取障害は必須項目のエラーとして表示する。旧 `readIfExists` と `listSubdirectories` は削除し、互換用ラッパーは残していない。

doctor は未走査・部分走査を消さず、取得失敗を正常な 0 件と区別して表示する。検証済みの証拠は `smt.json` / `quint.json` を読み、契約、backend名、対象モデルのハッシュ、利用不能状態、未完了理由を確認する。任意の JSON ファイル名だけでは検証済みに数えない。

Quint の deadlock 判定は、非ゼロ終了と標準エラーの完全な診断行 `error: reached a deadlock` の組合せに限定する。

## 実サンドボックス

リポジトリ外の一時ディレクトリへインストーラーで新規導入し、要件、参照検査、設計、リファインメントの4 intentを作成した。実 SMT と Quint / Apalache bounded を含む15回のセンサー実行とdoctorを確認した。

fixtureは既知の設計違反を含むため、センサー結果が `failed` であること自体はテスト失敗ではない。保存した15件のレポートでは、Quintはすべて bounded であり、利用不能・タイムアウト・実行失敗による脱落がないことを確認した。結果は `sandbox-sensors.json` と `sandbox-reports.json` に記録した。

同じ障害を基準コミットのバンドルと修正後のインストール済みバンドルへ投入した。

| 障害 | 修正前 | 修正後 |
| --- | --- | --- |
| domain / contract / functional の対象ファイルをディレクトリ化（3件） | exit 0、not-applicable、pass true | exit 1、io-failed、原因を標準エラーへ出力 |
| aidlc/spaces を通常ファイルへ置換 | 正常な 0/0 と表示 | 要件・設計・参照検査の3走査が取得失敗 |
| 要件検証のレポートを不正な random.json だけに置換 | 1/4 intent を検証済みと計上 | 0/4へ訂正 |
| 必須センサー定義を同名ディレクトリへ置換 | 設置済みと表示 | severity:error、未設置と表示 |
| センサー定義の親を通常ファイルへ置換 | 不在と読取障害を区別しない | severity:error、io-failedと原因を表示 |

前後の公開出力は `sandbox-faults.json` に保存した。障害投入後は元データを復元した。最終バンドルへの更新後に7ケースすべてを再確認し、インストーラーの再更新が `Changed 0` となることも確認した。

## 検出精度の確認

独立レビューで、変数への退避、条件式、関係ないENOENT文字列、異なる分岐の失敗結果などによるすり抜けを点検した。各ケースを個別fixtureで検証する回帰テストを追加し、危険な実装の検出と安全な対になる実装の受理を確認した。

このリンターは同一関数内の構文・型・取得元を追跡する検査であり、任意の関数呼出しを跨ぐプログラム全体の正しさを証明するものではない。終了コード、Result、実サンドボックスの故障注入を併用する。
