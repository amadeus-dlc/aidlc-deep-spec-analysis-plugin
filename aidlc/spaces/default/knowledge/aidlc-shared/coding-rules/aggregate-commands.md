# 集約のコマンドは整合性境界を守る

移植元: [amadeus-ngの同名規則](https://github.com/amadeus-dlc/amadeus-ng/blob/537c4e56a838a4cb28f6564d4c0add1d4adfe915/aidlc/spaces/default/knowledge/aidlc-shared/coding-rules/aggregate-commands.md)。2026-09-05にTypeScriptと当該の裁定へ適用し直した版。

## 規則

- 状態を変更する業務操作は集約が所有する。呼び出し側でフィールドの更新手順を組み立てない。
- 操作の事前条件と、成功後に成立すべき不変条件を明確にする。
- 通常起こりうる業務上の拒否はResultなどの結果型で返す。拒否した操作が中途半端な状態を残さないようにする。
- プログラムの契約違反を業務上の拒否として回復しない。panicの扱いは[エラーハンドリング](error-handling.md)に従う。
- 派生した結果やキャッシュが無効になる場合、その無効化も所有者の操作に含める。呼び出し順の注意事項だけに頼らない。
- 外界への保存はRepositoryが担当し、集約へI/Oを持ち込まない。

## CQSと不変変換

このリポジトリの集約にも[CQS](command-query-separation.md)を適用する。状態変更は`void`または`Result<void, E>`を基本とする。元の状態を変えず新しい集約を返す操作は、不変変換として区別する。

移植元の「1コマンド1イベント」「生成時に集約とイベントの対を返す」「履歴の再生だけで復元する」という保存方式の必須規則は取り込まない。ドメインイベントという概念を扱うことと、特定の保存方式を採用することは別である。
適用範囲と優先関係は[共有規則の入口](README.md)を参照。
