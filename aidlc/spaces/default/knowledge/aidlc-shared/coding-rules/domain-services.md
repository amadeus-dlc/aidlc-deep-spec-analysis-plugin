# ドメインサービスは最後の手段

移植元: [amadeus-ngの同名規則](https://github.com/amadeus-dlc/amadeus-ng/blob/537c4e56a838a4cb28f6564d4c0add1d4adfe915/aidlc/spaces/default/knowledge/aidlc-shared/coding-rules/domain-services.md)。2026-09-05にTypeScriptと当該の裁定へ適用し直した版。

## 原則

まず「この操作を所有する型はどれか」を考える。構築規則・導出・判断の所有者が決まるなら、その型の静的メソッドまたはインスタンスメソッドへ置く。

- 型の主要な生成経路を、無関係な自由関数やサービスへ置かない。
- 純関数であることや、仕様書でサービスと呼ばれていることだけを、新しいドメインサービスの根拠にしない。
- 複数の集約を扱う場合も、まずどの不変条件・業務判断の所有者なのかを確認する。
- 所有できる型がないと判断した理由は、コードと設計記録に残す。
- 新設時の人間の裁定は、既存のproject規則に従う。既存サービスの通常の改修に同じ承認を繰り返し求めない。

名前を決める前に、操作を対象の型から発見できる公開面を考える。コレクションの解析や集計なら、そのコレクションが操作を所有できないか検討する。
