# 整合性境界をまたぐ参照はIDで表す

移植元: [amadeus-ngの同名規則](https://github.com/amadeus-dlc/amadeus-ng/blob/537c4e56a838a4cb28f6564d4c0add1d4adfe915/aidlc/spaces/default/knowledge/aidlc-shared/coding-rules/aggregate-references.md)。2026-09-05にTypeScriptと当該の裁定へ適用し直した版。

## 原則

独立した整合性境界を持つ別の集約を参照するときは、そのIDを保持する。相手の現在状態を複製して、自分の正当な状態として維持しない。

- 相手のオブジェクトを便利だから埋め込むと、変更の責任と正となる状態が曖昧になる。
- フィールドをばらしてコピーしても、同じ状態を二重に所有する問題は解消しない。
- 判断に相手の情報が必要なら、必要な値やオブジェクトを操作の引数で受ける。保持しているIDと対応するかを確認する。
- 取得手段をドメインへ持ち込まない。ユースケースがportを使って必要な材料を用意する。

## 所有する子要素との区別

最初に整合性境界と所有関係を確定する。集約が所有するローカルエンティティ・値オブジェクト・コレクションの保持は、独立した別集約への参照とは異なる。クラス名に`Report`などが含まれることだけで、すべての包含関係をIDへ置き換えない。

その時点の検証証拠など、不変の記録を保持する場合も、相手の最新状態を複製しているのか、観測した記録を所有しているのかを明記する。
適用範囲と優先関係は[共有規則の入口](README.md)を参照。
