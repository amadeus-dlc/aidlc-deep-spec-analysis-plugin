# ファーストクラスコレクションの要素型

## 原則

ファーストクラスコレクションは、ドメイン固有のエンティティを要素として内包する。`string[]`、`number[]`、`Set<string>`や、生のプリミティブを含む汎用タプルを包むだけの型を認めない。これは個別チーム・プロジェクトの例外規則ではなく、共通の設計規律である。

- エラーの列には`ErrorMessage`を、列挙宣言には`EnumerationMember`を、束縛には`ScenarioBinding`や`BindingDeclaration`を使う。
- コンストラクタ・`of`・`add`は、ドメイン固有の要素を受け取る。生の基本型を受ける互換用の入口を残さない。
- 反復子や`toArray`も要素型を維持する。文字列やJSONへの変換は、必要な外部契約の境界で行う。
- 要素自身のサイズ・字句・構文・意味の契約は要素型が守る。コレクションは件数・一意性・順序など集合の契約を守る。
- コピーと走査は件数の検査後に行う。渡された配列を直接凍結せず、所有する配列を作る。
- 型名は初見で意味が分かる正式名を使う。`Fr`・`Br`・`Ir`だけでなく、`Attr`・`Req`・`Decl`・`Ref`・`Id`なども確認し、`FunctionalRequirementReferences`・`BusinessRuleReferences`・`IntermediateRepresentationVersion`・`Identifier`等へ展開する。公開文書の既存キー・プロトコル上の識別子は内部の型名と区別する。
- 通常のドメインロジックで想定内の不適合を扱う生成には`parse`を使い、Resultを処理する。データベース等からの再構成には`of`を使い、コンストラクタの検証を省略しない。`of`の例外を捕捉して入力エラーへ変換しない。
- 検証済みの要素から安全に構成できるコレクションには、基本型を引数に取る形だけの`static parse`を作らない。
- コンストラクタが件数上限・重複等で失敗しうる場合、型付き要素を受ける`parse`は必須である。要素のparseだけで完了とせず、コレクションのparseのResultも処理する。
- 同じ意味・契約・操作のコレクションを文脈別の名前だけで重複させない。共通のドメイン型へ統合し、旧名のwrapperやaliasを削除する。

## 共通の操作契約と非空の生成契約

2026-09-06のオーナー指示による。ファーストクラスコレクションは、Scalaのコレクションのように、要素アクセス・問い合わせ・変換を持つ操作契約として定義する。空判定だけの分類用インターフェイスでは足りない。

- `NonEmptyFirstClassCollection<E>` を共通操作の基底interfaceとし、`at`・`head`・`tail`・`include`・`exists`・`filter`・`map`と反復を定義する。
- `FirstClassCollection<E>` はこのinterfaceを継承し、`isEmpty(): boolean`を追加する。
- Eおよびmapの変換先Uは、`equals(other)`を持つドメイン型とする。`include`は要素自身の同値関係を使い、VOを参照一致や汎用のJSON化で比較しない。エンティティはその識別規律、VOは値の意味を守る。順序比較の一致を値の同値とみなさない。
- `map<U>(transform)`は変換後の要素型を持つ`FirstClassCollection<U>`を返す。生成先factory引数や、利用者向けinterfaceのSelf型引数は要求しない。
- `tail`・`filter`は空になり得るコレクションを返す。具体型の不変条件を保って再構築できる操作では、具体型の戻りを維持する。キー・所有者・モデル文脈を捨てた配列コピーで代用しない。
- `exists`は条件を満たす要素を見つけた時点で終了し、空ならfalse。callbackへ渡すのはelementだけとし、内部配列を追加引数として漏らさない。
- 空のhead/tail、無効なindexは操作の前提違反としてpanic相当の例外を伝播する。TypeScriptが保証する入力型を実行時に再検査しない。

この継承は操作契約を共有するものであり、interfaceだけで非空を証明するものではない。非空の具象型は `of(head: Element, tail: readonly Element[]): Self` とコンストラクタで保証する。非空型に常にfalseになるisEmptyを追加しない。命名は単数のtailで統一する。上限等の違反はofではpanic、parseでは自分の構築契約の非例外ParseErrorへ変換する。

走査・アクセス・短絡・変換のアルゴリズムは共通基盤へ集約する。具象型は反復する論理要素と再構築を提供し、要素数、一意性、順序、所属の契約をコンストラクタで守る。構築時の件数上限と共通操作の走査予算を整合させ、構築できた集合が通常操作の予算で拒否される不整合を作らない。各具象型が持つ、より厳しい上限も保持する。配列のlengthだけで完了せず、実際に保持するスナップショットを読取予算内で作る。具体的な上限値は対象ドメインの設計で定める。

static側はインスタンスのimplementsでは検査されないため、生成側の型契約でも照合する。コンストラクタの具体的な引数型を失わせない。範囲外アクセス、短絡、同値な別インスタンス、変換後の型、構造不変性、キーや所属を保つ再構築を公開APIで検証する。Semigroup/Monoidの結合操作は今回の共通契約には含めない。
