# ファーストクラスコレクションの要素型

## 原則

ファーストクラスコレクションは、ドメイン固有のエンティティを要素として内包する。`string[]`、`number[]`、`Set<string>`や、生のプリミティブを含む汎用タプルを包むだけの型を認めない。これは個別チーム・プロジェクトの例外規則ではなく、共通の設計規律である。

- エラーの列には`ErrorMessage`を、列挙宣言には`EnumerationMember`を、束縛には`ScenarioBinding`や`BindingDeclaration`を使う。
- コンストラクタ・`of`・`add`は、ドメイン固有の要素を受け取る。生の基本型を受ける互換用の入口を残さない。
- 反復子や`toArray`も要素型を維持する。文字列やJSONへの変換は、必要な外部契約の境界で行う。
- 要素自身のサイズ・字句・構文・意味の契約は要素型が守る。コレクションは件数・一意性・順序など集合の契約を守る。
- コピーと走査は件数の検査後に行う。渡された配列を直接凍結せず、所有する配列を作る。
- 型名は初見で意味が分かる正式名を使う。`Fr`・`Br`・`Ir`だけでなく、`Attr`・`Req`・`Decl`・`Ref`・`Id`なども確認し、`FunctionalRequirementReferences`・`BusinessRuleReferences`・`IntermediateRepresentationVersion`・`Identifier`等へ展開する。公開文書の既存キー・プロトコル上の識別子は内部の型名と区別する。
- 通常のドメインロジックで想定内の不適合を扱う生成には`parse`を使い、Resultを処理する。データベース等からの再構成には`of`を使い、コンストラクタの検証を省略しない。`of`の例外を捕捉して入力エラーへ変換しない。
- 検証済みの要素から安全に構成できるコレクションには、基本型を引数に取る形だけの`static parse`を作らない。
- コンストラクタが件数上限・重複等で失敗しうる場合、型付き要素を受ける`parse`は必須である。要素のparseだけで完了とせず、コレクションのparseのResultも処理する。
- 同じ意味・契約・操作のコレクションを文脈別の名前だけで重複させない。共通のドメイン型へ統合し、旧名のwrapperやaliasを削除する。

## 共通の操作契約と非空の生成契約

2026-09-06のオーナー指示による追加。空を許すファーストクラスコレクションには `FirstClassCollection` の `isEmpty(): boolean` を実装する。これは所有する要素がゼロかという問いであり、診断がない・比較の組がない・発行予算がないという意味には使わない。

反復を公開する型は、独立した `IterableFirstClassCollection<ドメイン固有の要素型>` を実装する。反復を公開しないコレクションへ、共通化のためだけに反復・配列変換・汎用加工操作を追加しない。集約や複数の集合を関連付ける評価結果は、反復を委譲することだけを理由にコレクションへ分類しない。

非空を保証する型に `isEmpty(): false` は置かない。生成を `of(head: Element, tail: readonly Element[]): Self` とし、必須の先頭要素で非空を型に表す。`parse` とコンストラクタも同じheadとtailの具体型を使う。命名は単数の `tail` で統一する。上限などの値制約はコンストラクタで検査し、ofはpanicとして伝播、parseは自分の構築契約の違反を非例外のParseErrorへ変換する。空かもしれない一般配列は呼出境界で空を明示的に扱い、非空型へのキャストや配列だけを受ける互換入口を作らない。

static側はインスタンスのimplementsでは検査されないため、`FirstClassCollectionFactory`・`FallibleFirstClassCollectionFactory`・`NonEmptyFirstClassCollectionFactory`の型契約でも照合する。コンストラクタの具体的な引数型を失わせない。固定の非空内容だけを生成する型は、実際の生成操作の契約を確認する。

これらのインターフェイスは操作と生成の契約である。要素数の上限、所有権、順序、一意性、非空の維持はコンストラクタとドメイン操作が保証し、公開APIのテストで検証する。コレクションの要素を増減させる操作の戻り型も、空になる可能性に従って選ぶ。Semigroup/Monoidの結合操作は、必要なドメインの意味と法則を確認して個別に設計する。
